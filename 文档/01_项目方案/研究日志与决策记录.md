## 如何记录

有实质进展时及时记录，最迟在任务结束、代码提交或交接前完成。同一次紧密相关的工作合并为一个条目，不记录无意义流水账。

执行者使用真实姓名或已知身份；AI 可写“Codex（AI）”。不推断用户姓名，不把 Git 作者自动当成实际贡献人。复核未发生则明确写未复核。

历史讨论在本文件建立前发生的，标注“回溯整理”，不伪造当时的精确时间或事前假设。不能以事后解释替代事前预期。

### 新条目模板

复制以下结构，分配未使用的 `RYYYYMMDD-NN` ID。所有字段都应回答；不适用或未知如实写明。

```text
### RYYYYMMDD-NN｜简短主题
- 日期/记录性质：北京时间日期；实时记录或回溯整理。
- 状态：已完成 / 已确认决策 / 拟议待确认 / 进行中 / 失败或阻塞。
- 执行者与贡献：谁提出、核查、实现或解释了什么；未知则写未知。
- 问题与事前预期：要解决什么；预期是否在结果之前记录。
- 决定与理由：采用什么，替代方案为何未采用；影响范围。
- 实际操作与证据：数据/配置/结果/文档相对路径、来源链接、代码版本；未提交改动明确说明。
- 结果与验证：真实结果、检查及其范围；未运行则说明。
- 解释与局限：能支持什么，不能支持什么；负结果也保留。
- 复核：复核人、内容与状态；未复核则说明。
- 下一步：具体动作；更正或替代旧决定时引用旧 ID。
```

### 为小组展示额外保留什么

从出现真实分析结果时起，在对应条目中按需补充以下信息，不必每次全部填写，也不另抄一套原始数据：

- **一句话发现及证据**：适合向同学解释的结论，连接实际结果表/图和数据版本；尚未验证的假设不要写成发现。
- **数字的口径**：研究哪段时间、多少场、分母是什么、排除了什么；相关差异或区间也链接计算结果，不只留下截图。
- **展示用图与重做方法**：图文件、生成入口和配置；论文/网页图片注明来源及使用限制。
- **一个具体案例**：哪场比赛或哪项处理最能说明问题，原始值、处理后值、理由与证据；需要时留可分享的必要截图。
- **讲解和局限**：这项结果说明什么、不能说明什么；记录失败结果和可能被问到的问题。
- **实际贡献与复核**：本人姓名、完成内容、可定位文件和验收情况，说明 AI 辅助范围；没有发生的人工复核不能提前记入。

日志是素材和依据，最终 PPT 应按研究问题组织，不按聊天或开发日期逐条照搬。最终采用的数字与图表统一绑定选定数据/分析版本；换版本后重新核对。

3. **图表与重做方法**：目前没有研究结果图；可根据设计第 1/2 节制作研究流程图，标为方法示意，不编造指标曲线。
4. **具体案例**：暂缓“修正能否提升预测表现”，保留“控制赛前实力后是否仍有主场信号”；前者与后者不是同一问题。

3. **图表与重做方法**：当前没有正式数据覆盖图；可从登记清单和 input_audit.json 整理资料概况。src.snapshot --verify 检查指纹，audit 可重出覆盖统计，不重新下载代替核对。

### 素材三：清洗做了什么，为什么不直接删疑点

1. **一句话发现及证据**：第一版统一格式并隔离无法自动裁定的记录，保留每条输入的去向。证据：[运行小结](../../outputs/logs/data_prep/clean-20261023T014412125078Z-82241e6c/clean_log.md)、同目录 quarantine.csv、issues.csv、row_lineage.csv。
2. **数字口径**：49,945 = 纳入 48,102 + 截止日后 1,803 + 暂隔离 40。截止日为 2024-12-31，保留热身历史。40 条属于 20 组同日同双方候选，不等于已证实 40 条错误。净胜球至少 5 的 3,319 条仅警告，未因此删除；这是全快照审计计数。
3. **图表与重做方法**：尚无正式清洗图；可按这些互斥数量制作样本去向示意。src.clean --config config.json 重做，使用其输出的实际版本；问题条数不可替代比赛数。
4. **具体案例**：1974 年 Tahiti/New Caledonia 记录可能来自多场比赛和不精确日期，暂隔离而非自动保留首条。RSSSF 链接见 R20261020-02；外部事实仍待成员核验。
5. **讲解和局限**：隔离也可能排除了真实比赛，会影响早期历史，不能当作已恢复全部真实赛果。点球辅助资料另有 1 条未匹配、37 条待核验，不与 40 条相加称总删行数。
6. **实际贡献与复核**：Codex（AI）实现和运行程序，用户完成 PyCharm 重跑。没有记录表明 A/B 已核验或批准修正；当前实际应用事实修正为 0 条。

### 素材四：怎样知道程序不是碰巧跑通

1. **一句话发现及证据**：人工小样例测试通过，重复运行结果相同，并有独立输出检查。证据：tests 下两份测试、R20261021-05、[最新验证报告](../../outputs/logs/data_prep/clean-20261023T014412125078Z-82241e6c/validation_report.json)。
2. **数字口径**：2026-10-21 记录 34 项测试通过，两次全量本机运行主表与逐行追踪指纹一致；10-23 用户运行的验证报告 passed=true。不是 34 场真实比赛核验，也不是多台电脑复现。
3. **图表与重做方法**：可展示少量测试/验证报告片段，不把控制台截图作足球效果图。按 README 运行 pytest 与 src.validate；不要将当前没有运行的新测试写成通过。
4. **具体案例**：测试明确检查 FALSE 不被读成 True、点球胜者不把主表平局改成胜利、失败不覆盖旧版。用户的 PyCharm 单文件启动错误通过正确的模块配置解决。
5. **讲解和局限**：程序检查通过不证明每场历史事实正确；版本仍为 human_review_pending=true、frozen=false，没有完成独立组员和跨电脑核验。
6. **实际贡献与复核**：Codex（AI）实现测试和验证，用户实际修正运行配置并重跑；初次测试权限与 Windows 编码失败及修复都保留在日志，不能美化为首次即成功。
