# 补充数据获取清单与爬虫需求

编制：2026-10-20。适用于本项目的数据准备、外部排名比较及可选的未来比赛预测。

本文回答：去哪些网站、取得什么内容、用什么方式、保存到哪里，以及什么时候值得写爬虫。它与[数据准备全流程指南](数据准备全流程指南.md)配套使用。本文列出的文件是计划产物，不代表已经下载或创建。

## 1. 获取范围与先后顺序

主数据继续使用 `data/raw/international_results/` 中的现有文件，主实验窗口截至 2024-12-31。先登记和审计现有文件，再针对实际疑点取证，不把多个网站的历史比赛直接拼成新主库。

按以下顺序推进：

1. 必做：现有快照登记；针对比分、日期、球队身份、场地问题的核验资料；必要的跨源队名映射。
2. 建议做：同日、同批球队的外部 Elo 排名快照，用于一致性分析。
3. 可选：FIFA 官方排名快照，作为另一种排名参照。
4. 未来预测启用后再做：官方未来赛程、举办地、开球时间，以及现有数据截止日之后的新赛果。
5. 暂不采集：全球阵容、伤病、身价、裁判、观众人数、赔率。近期状态、休赛时间和赛程密度优先从已有比赛派生。

当前最小版本不需要爬虫，也能完成主研究。爬虫应服务于明确且重复的数据需求，不能作为研究进度的替代品。

## 2. GitHub 主数据：登记现有文件，扩展时下载新快照

入口：[martj42/international_results](https://github.com/martj42/international_results)。

### 需要什么

- `results.csv`：比赛日期、球队、比分、赛事、城市、举办国家及 neutral。
- `shootouts.csv`：点球大战及胜者。
- `former_names.csv`：历史名称辅助核验。
- `README.md`、`LICENSE`：口径和许可。
- 已有 `goalscorers.csv` 保留，暂不另行更新进球者数据。

这些文件当前已经在本地，无需重新下载。先生成 manifest，记录哈希、字段、行数、实际覆盖日期和已知来源。上游 commit 未确认时留空，不能将上游最新 commit 当作本地副本版本。

如果启用 2026 年未来预测，先检查现有文件最新日期。已包含的 2025—2026 年比赛无需重复下载；对于后续已完赛比赛，再取得一个独立的新快照，补足到预先确定的预测信息截止日。

### 怎样取得

使用 GitHub 的文件下载、仓库 ZIP 或固定 commit 的原始文件下载。固定 commit 的 URL 形式为 `https://raw.githubusercontent.com/martj42/international_results/<已核实commit>/results.csv`，其中占位符必须替换为实际版本。

保存新完整快照，不只保存无法复原的临时差集。比较新旧快照时检查新增、修改和删除记录，不能简单假设上游只追加行。合并规则与采用版本另行登记。

### 是否需要爬虫

**不需要。** 原始 CSV 下载脚本属于文件下载，不需要遍历网页或解析页面。今后可以自动化下载、校验、缓存和版本登记。

原始快照继续放 raw；更新版可放 `data/raw/supplemental/international_results/<批次>/`。未来应用更新与截至 2024 年的主实验快照分别管理。

## 3. 官方足协及赛事报告：关键事实核验的首选

入口包括：[FIFA](https://www.fifa.com/)、[UEFA](https://www.uefa.com/) 和有关国家足协。具体国家足协页面在遇到案例时登记，不预先罗列所有网站。

### 需要什么

仅获取疑点比赛的具体报告：日期、双方球队、赛事、实际举办城市/球场、比分、是否加时、点球结果，以及比赛认定或改期说明。

### 怎样取得

人工打开比赛报告；官方提供 PDF 或数据导出时优先下载。没有下载入口时记录报告链接、访问时间和必要的事实提取。允许保留的资料放入 `data/raw/supplemental/official/<批次>/`，每份对应 evidence_id。

场地位于第三国不意味着可以不看上下文就自动标为中立；有官方“主队”标签也不一定意味着普通主场优势。最终使用项目已固定的场地规则。

### 是否需要爬虫

少量问题核验：**不需要**。

大量同赛事报告：可能需要定向页面提取，但必须先确认访问及使用条件。原始下载、静态 HTML 解析和动态网页自动化应分别记录，不能笼统声称都存在可用 API。

## 4. RSSSF：历史日期、比分、赛事与身份疑点

入口：[档案导航](https://www.rsssf.org/guide.html)；当前案例：[New Caledonia 历史赛果](https://www.rsssf.org/tablesn/newcal-intres.html)。

### 需要什么

问题所涉及球队/赛事/年份的相关记录及注释，包括日期精度、比分视角、举办地、赛事性质和资料不确定性。

当前应优先核验 1974 年 2 月 Tahiti 与 New Caledonia 的记录。该档案列出多场比赛但具体日期不明，不能据此补出准确日期，也不能将比分相反的记录直接当成重复删除。

### 怎样取得

从审计问题清单逐案定位具体档案，先人工提取。需要保存时，按来源允许的方式保存相关页面或小范围提取结果；登记维护者、更新时间和具体链接。RSSSF 是主数据声明的上游来源之一，属于来源追溯。

结构化结论写入 `data/external/evidence.csv`，获准保存的原始资料放 `data/raw/supplemental/rsssf/<批次>/`。

### 是否需要爬虫

少量案件：**不需要**。

大量同格式历史列表：可以考虑静态网页解析。但不同页面格式、未知日期、球队视角和注释处理可能不同，应逐类验证解析器，不能一套规则盲扫全站。

## 5. National Football Teams：全球单场及球队年度档案

入口：[National Football Teams](https://www.national-football-teams.com/)。

### 需要什么

疑点比赛的日期、对手、比分、赛事，以及页面实际提供的球场、阵容和备注。阵容只在核验球队身份或解释案例时少量提取，不批量扩充主模型。

### 怎样取得

按球队、年份、比赛逐级查找并人工登记证据。没有写明的内容保留缺失；网页没有收录一场比赛，也不能单凭这一点认定主数据应删除。

结论存 evidence.csv；如允许保存资料，放 `data/raw/supplemental/national_football_teams/<批次>/`。

### 是否需要爬虫

当前核验：**不需要**。

若核验数量显著增加，可以考虑限范围、低频率的页面采集。此次未确认其提供可自由批量获取的官方 API 或统一完整下载包；实施前再检查条款与访问条件。

## 6. 11v11：比分口径与具体比赛细节

入口：[11v11](https://www.11v11.com/)；[世界杯决赛记录示例](https://www.11v11.com/matches/argentina-v-france-18-december-2022-377810/)；[使用条款](https://www.11v11.com/terms-and-conditions-and-privacy-policy/)。

### 需要什么

少量比赛的常规时间比分、加时后比分、点球结果、日期、球场及必要备注。示例页面能区分 90 分钟、加时和点球，适合核验目标口径，但不能假设每场都有相同细节。

### 怎样取得

人工查看并记录必要事实、链接和核验结论。网站条款限制复制和再分发，因此不要把整站内容或批量页面作为项目数据包提交。需要超出条款允许的复制或再分发时，应先取得相应许可。

### 是否需要爬虫

**当前不安排爬虫。** 它适合作为人工核验来源，投入整站采集成本与使用限制不符合本项目需要。

## 7. Wikipedia：寻找报告与历史线索

入口：各国家队的赛果列表及具体比赛条目，例如[阿根廷国家队赛事列表](https://en.wikipedia.org/wiki/Argentina_national_football_team_results_(2020%E2%80%93present))。

### 需要什么

具体比赛的日期、比分、场地、备注及脚注，重点提取通向赛事/足协原始报告的链接。

### 怎样取得

优先人工追查引用。实际使用条目内容时，保存固定版本链接或修订 ID、访问时间、具体字段及引用来源。将同源转述与独立证据区分开。

如需大范围提取，优先查阅 Wikimedia 的[官方 API 文档](https://www.mediawiki.org/wiki/API:Main_page)，实施时再确认具体接口、访问政策与内容许可。公开接口不等于可以不署名复制所有内容。

### 是否需要爬虫

少量核验：**不需要**。

批量版本化获取：可能使用官方 API，而不必编写浏览器爬虫。当前不批量下载所有国家队列表。

## 8. EU-Football：暂列备用，不列为必须下载

入口：[eu-football.info](https://eu-football.info/)；[Wikidata 归档标识说明](https://www.wikidata.org/wiki/Property:P3726)。

本轮原站未能访问，不能确认其当前稳定可用性、全量覆盖或下载能力。其历史数据库身份有记录，但不是足协官方报告。

需要时尝试查找可读的具体比赛存档，核验欧洲比赛的阵容、球场或历史细节，并同时登记原始 URL、存档 URL、存档时间和访问时间。

**不安排爬虫，不为恢复这个站点投入主线工时。** 不可用时改用官方资料、RSSSF 或其他可访问来源；没有证据就保留不确定性。

## 9. eloratings.net：外部评级快照

入口：[World Football Elo Ratings](https://eloratings.net/)、[方法页](https://eloratings.net/about)。

### 需要什么

指定评级日期的球队名称、名次、Elo 分值和页面提供的必要状态说明；同时记录该系统的方法来源。

首版建议先选一个能取得且与主实验窗口相容的日期，获取与自建评级共同覆盖的球队。可以使用全部可匹配球队；若仅选部分球队，事先记录抽取规则，不能只挑相关性高的球队。

### 怎样取得

先在浏览器确认目标日期和表格，能复制时人工导出成 CSV 并复核行数、数值及并列名次。目标历史日期无法取得时，不用当前排名冒充，也不为此更改主实验窗口。

本轮网页读取对动态内容的支持不稳定，方法页也未读到完整方法正文。开发前需检查实际页面行为，不能先假定某个历史下载接口可用。

快照按评级日期保存到 `data/external/ratings/elo_<评级日期>.csv`，保留来源原名与规范球队 ID，登记取得时间和证据链接；有获准保存的原始文件则另存 raw。

### 是否需要爬虫

单日快照：通常先尝试人工获取，**不要求爬虫**。

大量历史日期或多支球队长时间序列：**可能需要动态网页采集或页面数据提取**，前提是访问方式和使用条件允许。此次未确认正式公共 API，不猜测未验证的接口。

用途仅为排名一致性与差异案例，不能作为程序正确性的标准答案，也不回填我们的历史 Elo。

## 10. FIFA 官方排名：第二种外部排名参照

入口：[男足排名](https://inside.fifa.com/fifa-rankings/world-ranking/men)、[计算方法](https://inside.fifa.com/fifa-rankings/world-ranking/procedure-men)。

### 需要什么

指定官方发布日期的球队、排名、积分，以及正式排名状态和方法说明。2018 年方法变化应记录；不直接拼接不同方法时期的积分尺度。排名并非半年发布一次，按实际发布日期取值。

### 怎样取得

先确认官方页面可选的历史日期。如果有明确下载入口则直接下载；没有时，人工导出少量指定日期的表格并复核。不要把动态/实时排名状态当成已正式发布的历史快照。

保存到 `data/external/ratings/fifa_<官方发布日期>.csv`。与自建 Elo 比较时，使用同一日期边界和共同球队，不比较不同系统的绝对分值。

### 是否需要爬虫

少量快照：**不需要先写爬虫**。

长期历史序列：可能涉及动态网页或公开允许的页面数据请求，需先验证真实数据来源、日期含义和使用条件。此次未确认通用的官方历史 CSV 下载或公共 API。

本项目建议作为可选旁证，不让历史采集难度阻塞主线。

## 11. FIFA、UEFA 及足协赛程：未来预测启用后获取

入口：[FIFA 国际比赛日历](https://inside.fifa.com/de/tournament-organisation/international-match-calendars)、[UEFA 欧国联赛程](https://www.uefa.com/uefanationsleague/fixtures-results/)、[2026/27 欧国联时间安排](https://www.uefa.com/uefanationsleague/news/0298-1d6ef1acfaef-b54fcf1da859-1000--2026-27-uefa-nations-league-all-you-need-to-know/)，以及参赛足协的比赛公告。

### 需要什么

赛前获取：稳定的比赛 ID、双方球队、赛事/轮次、计划开球时间及其时区、球场/城市/国家、场地核验状态、赛程状态和具体来源。

开球时间建议同时保存来源时区与 UTC。时间未知就写未知；页面球队排列不能替代场地核验。改期或换场时追加赛程版本，不覆盖已归档的预测输入。

赛后获取：正式比分、加时/点球说明、是否完赛/取消/中止及结果来源。赛后结果独立保存，不能写入原来的赛前输入。

### 怎样取得

第一版事先选定一个范围，例如某一轮全部符合条件的欧国联比赛，然后人工整理官方赛程。比赛 ID 与队名映射复核后，生成冻结的 fixtures 文件。

计划保存位置：`data/external/fixtures/<批次>/fixtures.csv`；赛程原始资料按允许方式存 raw；程序生成的概率与冻结信息存 `outputs/predictions/<批次>/`。

预测模型参数先冻结，再重放 2025—2026 年已完成比赛以更新球队状态。更新数据的覆盖缺口必须说明，不能假装已取得所有近期赛果。

### 是否需要爬虫

单个比赛日：**人工整理即可**。

需要定期同步多个赛事的改期、场地和赛果：**可能需要动态页面采集或允许的官方数据接口**。先验证取得方式，再决定实现；不把短期课程项目变成实时赛程平台。

2026 年 11 月国际比赛窗口为 9—17 日，欧国联相关轮次为 12—14 日及 15—17 日，部分赛果晚于课程 11 月 13 日截止。具体开球时间还应按官方更新换算到北京时间。因此可以在报告中交付冻结预测，但不能承诺截止前完成全部赛后复盘。

## 12. 保存取得过程：每一份资料都要留什么

统一使用前一份指南规定的 sources.csv、evidence.csv、team_aliases.csv 和 amendments.jsonl，不再增加另一套重复登记表。

- 来源登记：站点、具体入口、用途、取得方式、已知访问/分发限制、是否仍可访问。
- 逐条证据：case_id、具体 URL、页面标题、页面版本、访问时间、字段、原文取值、标准化取值、提取人、复核情况。
- 下载文件：相对路径、SHA-256、字节数、字段/行数、实际覆盖时间、取得时间；未知的原始下载时间明确标注未知。
- 排名及赛程：额外保存“资料对应日期”和“取得时间”，二者不能混用。
- 事实修改：原始记录身份、旧值、新值、理由、证据 ID 和追加式审批/撤销事件，不直接改 raw。

研究过程中有意义的采集决定、获取失败、范围变化及其影响，追加到计划维护的 `研究日志与决策记录.md`；逐行修改仍由结构化日志负责。

## 13. 爬虫投入的边界和验收要求

只有人工获取成本明显增加、字段稳定且允许自动访问时，才实施爬虫。先做一个小范围样本，人工核对通过再扩大。

实现时应具备：限范围 URL 清单、超时、有限重试、按站点条件控制频率、本地缓存、异常日志、来源时间与哈希。遇到验证码、权限或访问限制不绕过，改用允许的下载方式、人工记录或其他来源。

解析必须检查表头、字段和页数；尤其防止动态页面只取得空壳、分页只拿第一页、错误页被存成 CSV、比分方向相反、加时点球混淆、球队映射导致多对多关联。

正式复现从本地固定资料读取，不能依赖网站此时是否可用。对于不能随项目分发的资料，保存允许分发的必要结构化记录，并说明获取与复核方式，不承诺别人可以离线重建整个第三方网站。

## 14. 本轮应落实的获取任务

1. 登记本地主数据快照，完成只读审计；此时无需访问所有站点。
2. 从审计问题清单选出必须核验的案例，在官方报告、RSSSF、National Football Teams、11v11 中按需查找并登记。
3. 完成核验所需的队名映射和有证据的修改记录，进入清洗与质量验证。
4. 主线稳定后，尝试一份目标日期的外部 Elo 快照；可取得再做比较。
5. 仍有时间再加 FIFA 排名；启用未来预测时再获取官方赛程及更新版主数据。

截至本文编制，已核对主要网站入口和相关说明，但没有下载上述补充数据，也没有确认所有站点的批量采集权限或接口。网站可访问与可自由批量下载是不同判断；实际取得的数据以项目来源登记为准。
