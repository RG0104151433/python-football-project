## 二、阶段二操作步骤（目标：拿到可复现的冻结快照）

### Step 0. 初始化版本管理与骨架（0.5 小时）

在项目根目录执行：

```powershell
git init
```

`.gitignore` 至少排除：`.venv/`、`__pycache__/`、`*.pyc`、`.idea/`、`.ipynb_checkpoints/`。
注意：`data/raw/` 的冻结快照**要提交**（它是复现的根据）；`outputs/figures|tables|logs` 也建议提交（图和结果要进报告）。

建目录：

```text
data/raw/            原始快照，禁止手改
data/processed/      清洗后数据
data/external/       外部评级、队名映射
src/                 collect / clean / elo / features / evaluate / plots
notebooks/           探索过程
tests/               关键公式与防泄漏检查
outputs/figures/     图
outputs/tables/      表
outputs/logs/        日志
```

同时新建 `config.json`（所有可变参数集中在这里，不写死在代码里）：

```json
{
  "data": {
    "cutoff_date": "2024-12-31",
    "raw_dir": "data/raw",
    "processed_dir": "data/processed"
  },
  "elo": {
    "initial_rating": 1500,
    "K_candidates": [10, 20, 40],
    "H_candidates": [0, 50, 100],
    "goal_difference_mode": "none"
  },
  "time_split": {
    "warmup_end": "1979-12-31",
    "train_end": "2014-12-31",
    "valid_end": "2019-12-31",
    "test_end": "2024-12-31"
  },
  "random_seed": 42
}
```

> 时间划分是**建议示例**，必须在看过样本量与覆盖、且在查看测试表现之前确定；先写进 config 再跑数据，避免事后调参。

### Step 1. 写 `src/collect.py`（2—3 小时，本阶段唯一的代码产出）

必须实现的要点（照抄实施方案第 4 节的硬性要求）：

1. 数据源固定为 `martj42/international_results` 原仓库，下载三个文件：
   - `results.csv`（主数据）
   - `shootouts.csv`（点球大战识别，700 行）
   - `former_names.csv`（队名沿革，36 行）
2. 每个文件记录并保存到 `data/raw/manifest.json`：来源 URL、上游 commit、下载时间、**SHA-256**、实际行数、实际起止日期、字段列表、许可说明。
3. 校验：HTTP 状态码必须是 200；内容首行必须是预期表头；**绝不能把错误网页当成 CSV 存下来**。
4. 网络策略：超时设 90 秒、失败重试 3 次、失败要打印明确错误而不是静默跳过；已有本地快照时默认**不重新下载**（正式复现走离线快照）。
5. 上游 commit 用 GitHub API 取 `https://api.github.com/repos/martj42/international_results/commits?per_page=1` 记录到 manifest。

### Step 2. 冻结数据窗口（10 分钟）

在 `config.json` 固定 `cutoff_date = 2024-12-31`。所有后续分析只读 `data/processed/` 里窗口内的数据；2025—2026 的比赛作为"预留扩展"，不进入主实验，除非事先约定。

### Step 3. 写 `src/clean.py`（3—4 小时）——清洗规则清单

| 规则 | 具体做法 | 产出 |
|---|---|---|
| 日期解析 | 统一 `YYYY-MM-DD` → datetime，保留原始行号 | 新列 `date_parsed`, `row_id` |
| 比分检查 | 必须是非负整数；空值/非数字进隔离清单，**不填 0** | `outputs/logs/quarantine.csv` |
| 重复与异常 | 重复 (date, home, away) 组合列清单；异常比分**核实后**再处理，不因罕见就删 | `outputs/logs/duplicates.csv` |
| 中立场解析 | `neutral` 是字符串 `TRUE`/`FALSE`，**绝不能用 `bool('FALSE')`**（在 Python 里那是 True） | 布尔列 `is_neutral` |
| 主场归属 | `home_team` 是数据中的第一方；中立场不能自动加主场分；历史国名不一致时不能只看名称相等 | 依赖 `former_names.csv` 显式映射 |
| 队名映射 | 跨源队名用**显式映射表**，不靠模糊匹配直接合并；历史队伍继承与解体球队单独说明 | `data/external/team_alias.csv` |
| 赛果口径 | 原比分**含加时、不含点球**；目标定为"含加时不含点球的主胜/平/客胜"，不得称"90 分钟赛果" | `outcome` 三分类列 |
| 可追溯性 | 保留日期与原始行号，保证确定排序；若无开球时间，按日统一取赛前评级、赛后批量更新 | 清洗日志 |

**清洗日志**必须记录每条规则处理了多少行，保留原始行 → 最终行的追踪，输出到 `outputs/logs/clean_log.json` 与一份人读的 `outputs/logs/clean_log.md`。

### Step 4. 写 `src/data_dictionary.md`（30 分钟）

逐字段说明：字段名、类型、取值范围、是否缺失、口径注意事项（尤其 `neutral`、`tournament`、`country`）。这是报告 Method 节和"数据溯源"要求的直接产物。

- [ ] 清洗日志 + 隔离清单 + 队名映射表齐全

## 三、阶段三（清洗后的 EDA，2—3 天）

### Step 6. 三张 EDA 图（`src/plots.py` 或 notebook）

1. 逐年比赛量与赛事构成（看覆盖与稀疏年份）；
2. 非中立场的主胜/平/客胜比例与净胜球分布（比例给 **Wilson 区间**）；
3. 按年代、友谊赛/正式赛的分组比较（主胜率随时间的变化；分组比较可用按年份/赛事时间块的**配对 bootstrap**，并声明它没有消除球队间依赖）。

每张图都要标明样本量、分母、时间范围；小样本年代不要过度解读。

### Step 7. 主场优势的表述纪律（写报告时直接照用）

- 主胜率高**不能**直接推出主场的因果效应：强队的赛程与比赛地点选择并非随机（自选择偏差）。先表述为**描述性关联**；
- 再用赛前 Elo 差分层或建模，看控制可观测实力后是否仍有主场信号；
- 中立与非中立比赛构成不同，**不能**只靠两组均值相减宣称因果。

## 四、2026-10-20 实测事实（供冻结时核对，勿再引用仓库 README 的行数）

上游仓库：`martj42/international_results`，最新 commit `d5bd6de012c8`（2026-10-10）。

| 项目 | 实测值 |
|---|---|
| `results.csv` | 3,764,617 字节；SHA-256 `5dcefd1aa0483979ea8378cef5be448d2005609d39945ea162378561a30a6767`；49,945 行数据 |
| 覆盖区间 | 1872-11-30 → 2026-10-06；337 个历史队名；213 种赛事 |
| 字段 | `date, home_team, away_team, home_score, away_score, tournament, city, country, neutral`（9 列） |
| `neutral` 取值 | 字符串 `FALSE` 36,669 / `TRUE` 13,276 —— 正是 `bool('FALSE')` 陷阱的来源 |
| 缺失比分 | 0 行空比分；重复 (date,home,away) 键 1 组；同队自赛 0 行 |
| 截止 2024-12-31 | 48,142 行；非中立 35,490（主 18,003 / 平 8,117 / 客 9,370，**主胜率 50.73%**） |
| 每十年比赛量 | 1870s 13 → 1950s 1,657 → 1990s 6,942 → 2010s 9,800（2020s 4,736，未满十年） |
| 大比分（≥5 球） | 4,511 行（约 9.4%），属正常范围，**不得因罕见直接删除** |
| `shootouts.csv` | 700 行；`former_names.csv` | 36 行 |

**网络实况（重要）**：
- `raw.githubusercontent.com` 可达，但 3.7 MB 需约 19 秒，**首次请求曾超时失败** → 采集脚本必须设 90 秒超时 + 重试；
- `github.com` 网页域名在本机被代理阻断（ProxyError），`cdn.jsdelivr.net` SSL 失败 → 备用镜像只能用 Kaggle（需账号）或 api.github.com（正常）；
- 因此"断网也能做分析"不是可选项，是必须项：快照要提交进 Git。
