## 1. 截图明确要求了什么

### 口头汇报

- 每组进行 **10 分钟口头汇报**，安排在第 9—11 周。
- 汇报时 **所有组员均需在台上**。截图未说明必须每人讲几分钟，不自行添加此要求。
- 每组最多 4 人，评分考虑成员实际贡献；本组 3 人没有超出人数上限。

直接证据：[要求页，87 号截图](../../参考资料/课程原始截图/微信图片_20260929224329_87_315.jpg)。第 9—11 周的具体日期、先后顺序和设备安排需以班级通知为准，现有截图不足以确定。

### 报告与提交

- 截图显示报告截止时间为 **2026 年 11 月 13 日 23:59**。
- 交付包括报告、完整代码、所用实验数据，同时还有课堂口头汇报。
- 报告可用 Word 或 LaTeX 准备，按模板包含：Introduction、Method、Experimental Results and Analysis、Discussion and Conclusion、References，并写题目与成员信息。
- 需同时交 python123 对应课程单元和指定邮箱；python123 只交报告与代码，不交数据；邮件交报告、代码、数据，分别打包为附件，每组只发一封。
- 邮件正文列项目题目，以及全体成员姓名、学号、班级、职责和贡献；主题遵循截图给出的 CourseProjectFall2026 开头及成员姓名/学号格式。正式提交前再核对原图，不把本文件的中文概述当成邮件模板。

证据：[截止日及提交页，86 号](../../参考资料/课程原始截图/微信图片_20260929224329_86_315.jpg)、[报告模板，89 号](../../参考资料/课程原始截图/微信图片_20260929224329_89_315.jpg)、[讨论与引用，90 号](../../参考资料/课程原始截图/微信图片_20260929224329_90_315.jpg)。当前只是核对，没有发送邮件或提交材料。

### 项目内容与报告讲解

- 使用 Python 和真实数据研究清楚的问题；数据分析是允许方向，截图没有要求必须训练机器学习模型。
- 代码至少 100 行，使用至少两种用于人工智能、数据挖掘或数据分析的 Python 库。
- 要有足够的数据分析、可视化和一定创新性；代码有足够注释、能运行、结果能复现，禁止捏造和篡改。
- 方法部分解释选择理由、实现和改进，可用流程图或算法提纲。
- 结果部分说明数据、评价依据，解释图表；适用时补充稳健性或消融，不等于所有课题都必须做预测消融。
- 讨论包括贡献、长处、限制、经验和后续改进；外部理论、算法、数据及图均须统一引用，复用代码也要引用并解释自身贡献。

## 2. HTML 能不能替代 PPT 做课堂展示

**现有截图没有要求必须 PPT，也没有明确批准 HTML。** 由此只能确认“未见载体限制”，不能断言老师已经允许 HTML。

建议将本地 HTML 作为拟用课堂载体，先向老师确认一句：

> 我们想用本地浏览器打开 HTML 做 10 分钟口头汇报，所有成员上台，报告和代码/数据仍按原要求提交。课堂展示可以采用这种方式吗？是否需要额外提交幻灯片文件？

这句话仅供本人询问，本轮没有代发。HTML 的交互适合解释“统一赛事配方”的权重变化；最终报告仍按要求准备，不能只交一个网页就认为报告已完成。保存 PDF 等静态备份是小组建议，不是截图中的强制规定。

HTML 方案若获确认，应做到：离线可用、本地字体/图片/脚本、页面可前后翻和全屏、默认显示已核查参考值、每页保留来源和版本；交互使用预先核查的数据，避免演示过程改变正式研究配置。给打印/导出留静态视图，提前在实际投影分辨率和教室设备排练。

书面报告、课堂载体、提交附件是三个不同问题。即使 HTML 用于课堂，也不能由此推断 python123 接受它作报告，或老师不再需要 Word/LaTeX 准备的正式报告。后续如有更新通知，以老师的明确答复为准并追加记录。

## 4. 现在固定的 HTML 内容与验收规范

2026-10-24 补充。以下是小组制作规范，不是教师额外规定；HTML 许可仍未确认。这一阶段先约定页面要讲什么、从哪里取数、怎样验收，不锁死配色或实现框架，也不提前制作完整网页。三题完成后统一装入最终页面。

### 第一题需要交给页面制作者的材料

以[阶段 README](../../研究/01_年代变化/README.md)指定的分析版本为准，提供现成的四屏提纲、三张图、展示数据包、图注和来源。页面不从研究日志中随意抽取数字，更不抄旧调试版本。当前第一题四屏及其必备内容为：

1. **问题和研究样本。** 前一段先讲基础清洗与会员再次确认，本屏再提出年代问题并标明选定版本、1980—2024范围与五年代。当前人工确认版为24,917场，旧26,055场仅作已标注的基线；不重复扣除前一段的排除数。
2. **原始表现怎样变。** 展示五个年代的主胜率及样本量；平局包含在分母，比分含加时、不含点球；最后一组明确标为 2020—2024、五年。放大纵轴要有清楚的刻度与提示，不能用面积或截断制造夸大的变化。
3. **统一配方后怎样。** 同时看见两类赛事的比例与表现，用共同比赛篮子解释标准化；明确 non_friendly 是“其他非友谊赛事”。原始/调整切换必须注明是否同样本，权重是共同构成，不能标为训练重要性。教学例子与真实结果分开展示。
4. **结论依赖什么。** 展示权重曲线、当前主参考及翻转点；列出尚无区间、没有控制全部实力、并非因果解释等限制。正式方法验收后再补区间和解释，不提前画误差线。用一句话衔接第二题“同一时期两类赛事有什么不同”。

每屏至少有一句中心结论、一幅主图或流程、必要口径和来源入口。第一题约2分30秒，完整流程细节、字典、公式与文献放附录，不能将所有表挤进主页面。当前24,917场的四屏讲稿和图注已补在[收尾提纲](../../研究/01_年代变化/收尾核查与汇报提纲.md)开头；这是内容草稿，不等于页面已制作或成员已经排练验收。

### 数据和交互必须遵守的规则

- 原始/标准化的默认视图、数字与图来自同一 analysis_id。页面附数据版本、分析身份、参考方案、推断状态及来源；源表和运行清单可置于附录，不在主屏铺满哈希。
- 当前版的主参考界面可显示38.5199%；年度等权值从同版reference_weights.csv读取，不沿用旧值。旧基线38.5339%及其年度等权40.4346%只在明确标注的基线对照中显示。概率显示为百分比，两个比例之差显示为“百分点”，不能混用。
- 友谊赛占比滑块范围为 0—100%，默认回到当前主参考；显示当前值、两类组内表现与明确重置按钮。滑动表示改变共同参考配方，不表示重训、预测或重新采集比赛。
- 若在浏览器重算，只使用既定分组率和已验证的标准化公式，并与已保存参考值及端点核对。要计算整个年代曲线，须使用逐年代×类型的组内率；不能只依靠两个年代对比的权重曲线冒充所有年代数据。
- 展示数据包嵌套原表包含字符串，明确将数值转换；空值保留缺失，不能用 Number('') 把它变成零。缺组时显示无法计算，不补零；任何未算区间明确写“未计算”，不解释成无不确定性。
- 交互所得探索值和正式保存结果分清。不得下载新数据、调用研究程序或修改研究配置；方法、数据或参考更新后重新导出并核查，不能只手改网页数字。

### 使用和排练验收

最终 HTML 应可在目标电脑断网后从本地直接打开，数据和必要资源内嵌或随包本地保存，不依赖 CDN、在线字体、远程接口或 file:// 下的 fetch。交付写清打开入口；准备静态 PDF 等备份。

主界面适配实际投影设备；先以 16:9、1920×1080 和 1366×768 检查无横向溢出、图例不遮挡、文字后排可读，最终仍需现场确认。标题、图例和脚注不能只靠颜色区分；可用键盘前后翻页，滑块可键盘操作，所有交互都有标签，关键结论在不操作时也可阅读。全屏采用浏览器正常功能，不强制或劫持按键。

验收时逐项留下实际记录：

1. 默认状态的年代数、样本数、主胜率、权重及差值与指定源表一致；显示舍入规则一致。
2. 原始/调整切换、两套参考、滑块端点和重置正确；缺失与未计算状态正确。
3. 断网、重新打开、键盘操作、不同分辨率和静态备份可用；由实际操作者签明范围，不提前填通过。
4. 全组三人计时排练，总时长符合老师要求；图注、引用、真实贡献和最终报告一致。

当前状态：已有统计数据、图和结构；尚无成品 HTML、浏览器/投影验收或完整讲稿。A/B 暂缓时可由组长与 AI 先整理内容，实际人员复核与排练以后按真实情况补记。无论最终使用 HTML 还是其他载体，以上数据与解释规范继续适用。
