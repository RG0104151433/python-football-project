#### 必须实际执行的检索路径

不要把国家成立/统一、首场比赛、洲足联加入、赛事参赛权或停权自动等同于FIFA会员加入/退出。临时与正式资格涉及研究口径时，记录原文并列待主线判断，不自行改政策。新闻报道与官方文件冲突要并列，不选对结果有利的一边。

## 交付格式与验收规则

统一UTF-8、LF换行。JSONL每行一个合法JSON对象；未知为null，数组用真实JSON数组，不使用NaN。ID在批次内唯一，跨文件引用必须能找到。路径相对仓库根目录；访问时间含时区。下面字段全部保留，不适用或未知用null/空数组并解释。

### evidence.jsonl：一条来源一行

- evidence_id：如本批次前缀加E001，避免与已有证据撞号。
- publisher、title、source_url、published_on、accessed_at：原发布机构、标题、具体地址、已知发布日期、实际访问时间。
- authority：fifa_primary / locating_lead。非FIFA材料只标线索，不标主证据。
- access_status：full_text_read / search_excerpt_only / unavailable。
- locator：页码、章节或文号；扫描件注明PDF页码与印刷页码的区别。
- local_path、sha256：实际保存文件及其哈希；没保存就都为null。
- supported_statement、limitations：用自己的话写支持事实及边界。

同一文件多个页码可在不同claim中分别定位，不必反复下载。同一事件的镜像/转载不当两份独立主证据。

### claims.jsonl：一项历史事实主张一行

- claim_id、source_team_id、source_team_label：本批次主张ID及现有来源球队ID/原标签；尚不能对应的主张，球队字段可null并解释。
- fifa_association_name、fifa_code：原文所指足协/代码；原文没提供代码可null，不靠猜测补。
- claim_type：admission / readmission / exit / suspension / succession / membership_observation / nonmembership / name_equivalence。
- statement：事实主张和对应对象，不将结果继承自动写成会员连续。
- event_date、event_year、date_precision：有确切日才填YYYY-MM-DD；仅年份时event_date=null、event_year为整数、date_precision=year；其他精度day / bounded_range / observation_only / unknown。
- date_bounds：只能由原文推得的日期范围，结构为earliest/latest两个可空ISO日期；不与实际会员有效期混淆。
- evidence_ids、evidence_locators：主证据ID数组，以及按ID定位的具体页码/段落。
- status：supported / partial / conflict / unresolved。
- limitations、checked_by、independent_review：局限、实际查证者、实际独立复核；未复核则明确null。

事实主张与本项目纳入判断分开。一个时点有会员记录，不代表此前或此后所有日期都已证明；精度不足时保留partial。

### case_assessments.jsonl：对任务中一组比赛提出建议

- assessment_id、source_team_id、source_team_label、original_pending_status：追踪回输入任务；若是额外复查246场加入前分类，original_pending_status如实填原状态并在reason说明。
- match_ids：仅使用现有完整match_id。每行只放同一球队、同一证据结论适用的一组比赛；日期前后判断不同就拆行。
- proposed_membership：member / non_member / unresolved / conflict，是比赛日期上的建议，不是已发布决定。
- claim_ids、evidence_ids：支撑建议的主张和证据引用。
- task_status：resolved / partial / not_found / conflict / not_reviewed。
- reason、remaining_gap：为什么能/不能确定、还缺什么。

只看到搜索摘要或没有FIFA主证据时，不把member/non_member建议标为resolved。判unresolved不是错误，也不等于非会员。相同球队×比赛不得出现相互矛盾的无冲突标识建议。

### search_log.jsonl：检索过程和负结果

字段为search_id、source_team_id、searched_at、query、searched_site、result_urls、outcome、notes。记录实际执行的检索，outcome为useful_source / lead_only / inaccessible / no_result。不把未执行的拟议搜索写成已查。

### README.md：给人看的交接

先写最有用的发现，再按任务类型说明进展；给出本批次主证据数、任务覆盖数、建议可处置的去重比赛数、仍未解决数和未查数。不同任务可能指向同一比赛，去重统计，不能用球队出场次数代替场数。说明未改变正式数据、未运行研究重算以及实际AI/人工贡献。

验收至少检查：JSONL可逐行解析；原文文件存在且SHA相符；ID引用有效；source_team_id和match_id来自输入且确实相关；日期与引用支持范围一致；官方依据和线索分清；冲突/未知保留；输入/发布包指纹未变。自己未执行的检查写未运行，不写“全部验证通过”。

后续由主线审核这些材料，将符合要求的主张转成生产规则，经预演、发布和两问重算后才生效。本交付不能直接填进旧amendments或review_decisions入口。
