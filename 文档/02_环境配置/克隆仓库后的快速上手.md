# 克隆仓库后，怎样在自己的电脑跑起来

更新：2026-10-23。先按 Windows 10/11、Intel/AMD 64 位电脑说明；macOS/Linux/ARM 用户先报告系统，不能直接套用 Windows 路径并保证锁定依赖可安装。

目标是：使用自己的 Python 环境，能检查原始数据、运行清洗并找到结果。不要复制组长的 .venv，也不要新建第二套同名项目。

## 1. 下载项目，找到正确目录

准备 Git、Python 3.14 64 位和编辑器。团队已验收基线为 Python 3.14.8；优先一致，若只能用其他 3.14 补丁版本，记录版本差异并完成验收。不要选 3.13、免费线程构建或嵌入式版本。

用 PyCharm 的“从版本控制获取”填组长提供的仓库地址并选择本地位置，或使用：

```powershell
git clone <替换为组长提供的仓库地址>
```

尖括号中的文字是占位说明，不要原样执行。下载后用 PyCharm 打开包含 README.md、config.json、src 的那一层目录。命令都在这一层运行，不进入 src 或文档目录。

拉取到的代码需要包含本次上手文档和最新功能；组长未提交推送的本机文件，其他人无法通过克隆获得。

## 2. 创建自己的虚拟环境

在 PyCharm 底部终端打开 PowerShell，先检查：

```powershell
Get-Location
py -3.14 --version
```

第一行应为自己的项目根目录，第二行应显示 3.14.x。没有 py 或没有 3.14 时，先安装/找到正确 Python，不随便用其他版本凑数。

新克隆通常没有 .venv，执行：

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe check_env.py
```

不需要执行激活脚本。安装依赖需要网络；后面的数据准备可以离线运行。requirements.txt 是完整版本清单，暂不自行升级；遇到安装失败，保存完整输出和 Python 版本给组长，不反复换版本。

如果已存在 .venv，先核对它是不是本机为此目录建立的；不要覆盖、删除或移动已在用的环境。界面或命令路径仍指向别的目录时先纠正。check_env.py 使用人工数据，不是研究实验。

通过后看到 ENVIRONMENT CHECK PASSED；本机报告在 outputs/environment_check/。它可能与仓库内组长报告不同，这是正常的本机记录，不要为了相同手改它；交验后提交前检查 Git 差异，未经约定不把个人解释器绝对路径等报告混入研究结果。

## 3. 让 PyCharm 使用这个环境

按 Ctrl+Alt+S，在设置里搜索“Python 解释器”。选择“添加解释器 → 添加本地解释器 → 现有环境”，浏览到**自己项目目录**的 `.venv\Scripts\python.exe`。不要照抄 EasonG 的完整路径。

再进入“运行 → 编辑配置”，点击＋，新增 Python 配置：

- 名称：数据清洗。
- 最上方解释器下拉框：选择刚添加的本项目环境；若只有旧目录环境，先完成上一步添加。
- 解释器选项：留空。这里不能填 python.exe，否则会把可执行程序当成代码读取。
- 将“脚本路径”切换为“模块名称/module”，填写 src.clean，不带 .py。
- 参数：--config config.json。
- 工作目录：自己项目根目录，即 config.json 所在目录。

先将参数临时改成 --help，运行看到帮助，再改回 --config config.json。以后选择这条配置运行，不右键 clean.py 作为单文件启动。更多界面说明看[PyCharm 教程](环境配置_PyCharm.md)，其旧个人路径只是历史示例。

## 4. 先检查数据，再运行清洗

在根目录终端依次执行：

```powershell
.\.venv\Scripts\python.exe -m src.snapshot --verify --config config.json
.\.venv\Scripts\python.exe -m src.audit --config config.json
.\.venv\Scripts\python.exe -m src.clean --config config.json
```

- snapshot 应通过。如果输入指纹不一致，先联系组长核对版本和 Git 行尾，不运行 --register 覆盖原清单，也不修改原始 CSV。
- audit 发现待核验关键记录时退出码是 1，表示已生成问题报告；这不是让你重装 Python。
- clean 显示数据版本、数量和报告位置，退出码 0 表示程序检查通过，不等于所有比赛已人工核验。
- 退出码 2 表示输入、配置等错误，按完整提示处理；不要无视失败继续报告成功。

当前相同输入和规则的参考结果为：原始 49,945，纳入 48,102，窗口外 1,803，隔离 40。以后版本变了也可能合理，先核对版本，不能为了对齐数量改数据。

## 5. 验证结果并运行测试

从清洗输出复制实际 data_version，替换下面的版本占位符：

```powershell
.\.venv\Scripts\python.exe -m src.validate --config config.json --data-version <实际版本号>
.\.venv\Scripts\python.exe -m pytest -q
```

版本例子是 prep-3fab808178cf8ad71d88。validate 应显示 passed=true；含年代分析的新测试参考为 48 项通过（早期仅清洗为 34 项），以本机实际输出为准。如果 tests 的临时目录权限有问题，交完整报错，不把“没能运行测试”写成通过。

数据在 data/processed/<版本号>/matches_clean.csv；字典在同目录。每次运行的报告在 outputs/logs/data_prep/clean-<运行时间与编号>/，先读 clean_log.md，再看 issues.csv、quarantine.csv、row_lineage.csv 和 validation_report.json。

## 6. 常见错误对照

清洗复现通过后，可以继续[第一题本地运行与复现](../../研究/01_年代变化/本地运行与复现.md)。它使用独立模块 src.analyze_eras 和 config/eras.json；根清洗配置不改。当前是探索性描述，不计算区间。

- attempted relative import：用了单文件启动，改成模块 src.clean；仅改工作目录不够。
- MZ、Non-UTF-8 且报错文件为 python.exe：把解释器路径填进了解释器选项，清空该框并在最上方下拉框选环境。
- 找不到 src：检查工作目录和模块名，不能在 src 子目录运行。
- 找不到 config.json：参数和工作目录不匹配。
- 模块/库未安装：确认安装依赖和运行时用了同一个 .venv，再看 pip 的实际错误。
- 原始哈希不一致：核对 Git 拉取版本和 .gitattributes，不重登记来消除报错。

## 7. 最后向组长交什么

本人电脑系统、Python 版本、解释器路径、环境检查结果、清洗版本、四项数量、验证结果、测试结果，以及遇到的问题。个人路径按团队需要分享，公开前遮掉不必要信息。

使用 AI 时先给它 README、AGENTS.md 和研究日志，要求如实记录操作。不要让 AI 擅自删除 .venv、更新全部依赖、重登记数据或改研究参数。继续工作前阅读[当前分工](../05_团队协作/分工与交付/00_先看这里.md)。
