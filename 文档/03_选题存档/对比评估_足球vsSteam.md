# 「足球 Elo」 vs 「Steam 生态」全链路对比评估

> 背景：课程为《Programming with Python, Fall 2026》期末项目，报告按五节学术模板（Introduction / Method / Results / Discussion / References）评分，硬性要求可复现、结果不得伪造，另设 10 分钟答辩。
> 评估口径：性价比（投入成本 ÷ 预期收益）、创新性（方案独特性与亮点）、老师评价预期（结合课程模板的学术规范导向）。评分 10 分制。

---

## 环节一：选题立项

**足球 Elo**
- 性价比 ★9：研究问题立项即成型——主场优势量化 + 自建评分体系 + 历史回测，三级问题链一天可定稿，无需试错。
- 创新性 ★8：本科课程项目里"自建模型"的姿态少见；三级问题链（描述 → 机制 → 预测）结构完整。
- 老师关注点：可能问"Elo 是现成算法，创新在哪"。对策：立项书里明确差异化——K 值与进球差修正是自主设计、验证协议自建、与官方排名对照是原创验证工作。

**Steam 生态**
- 性价比 ★7：问题边界（口碑？规模？定价？）容易发散，收敛讨论要多花一两次组会；需先定代理变量策略。
- 创新性 ★7："有人玩没人夸"的角度有想法，但游戏数据分析在课程项目中出现频率上升。
- 老师关注点：商业趣味问题可能被质疑学术性；立项阶段就要备好"这项分析对谁有用"的答案。

## 环节二：数据采集

**足球 Elo**
- 性价比 ★9：Kaggle 单个 CSV 全量 4.5 万场，半小时到位；验证数据对照官方排名即可，边际成本近零。
- 创新性 ★5：采集环节平淡（下载为主），是全项目唯一弱项。eloratings.net 为 JS 渲染站点，爬取成本偏高，不建议硬啃；可手工整理少量对照值。
- 老师关注点："数据是否单一来源"。对策：强调官方权威数据 + 双源验证（比赛结果 × 官方排名）结构。

**Steam 生态**
- 性价比 ★7：存档打底便宜；但拿采集环节的分必须补 API 现采（Steam 官方接口免 key 部分即可），有接口字段杂、限频的试错成本。
- 创新性 ★8：存档 + API 多源结构是管线亮点。
- 老师关注点：爬虫合规（robots、频控）大概率被点名；存档时间与现采时间的口径不一致需要显式处理。

## 环节三：执行实施（清洗、分析、建模）

**足球 Elo**
- 性价比 ★9：字段干净清洗极轻；主要工时在 Elo 实现与回测协议。**有官方"标准答案"参照，跑偏立刻能发现，调试成本天然低**——这是两项目最被低估的差异。
- 创新性 ★9：自建评分体系 + 主场优势效应量分解 + 回测协议设计，Method 节有独家内容，且不依赖高级模型。
- 老师关注点：实验协议严谨性是必查项——是否用了未来信息、K 值敏感性、新队初始分。这是最容易被挑的点，也是主动写透后最能拿分的点。

**Steam 生态**
- 性价比 ★7：类型多值字段、免费/付费分层、owners 区间转数值，清洗工作量中等；建模是常规回归 + 随机森林，要出彩需追加分层设计与个案挖掘，工时弹性大。
- 创新性 ★7：方法本身是标准套路，创新靠分析设计不靠算法。
- 老师关注点：**owners 精度是明显的扣分入口**（结论建立在区间估计上）；比例数据用 OLS 的合理性会被问。

## 环节四：成果产出（报告、图表、可复现性）

**足球 Elo**
- 性价比 ★9：图表清单现成——Elo 曲线、主场优势效应量图、"自己 vs 官方"对照散点图（一张图证明实现正确，全项目性价比之王）、回测准确率表。五节报告每节有实料。
- 创新性 ★9："用一张对照图证明自建系统正确"在本科报告里罕见，方法论叙事完整。
- 老师关注点：一键复现、References 规范、主场优势结论要有置信区间意识。

**Steam 生态**
- 性价比 ★8：散点/热力/分布图素材丰富，出图容易；但 Discussion 必须花大力气处理数据局限（owners、评测轰炸），写不好整份报告显单薄。
- 创新性 ★7：个案分析（差评如潮但在线人数高）是亮点素材。
- 老师关注点：局限性讨论是 Steam 的"必答题"，答不诚实就丢分。

## 环节五：展示答辩

**足球 Elo**
- 性价比 ★9：答辩叙事线完整——问题 → 方法 → 验证 → 发现，10 分钟自然填满不注水；可现场回放一场著名比赛的评分变化。
- 创新性 ★8："我们写了一个排名系统，并证明了它是对的"是有记忆点的收尾。
- 老师关注点：可能现场抽问算法细节（某队分数为何变），组员需吃透公式，准备成本不高但必须做。

**Steam 生态**
- 性价比 ★8：现场演示效果最好（对着 Steam 页面指认数据点），互动强；但多个平行小发现需要精心组织成一条主线，否则答辩散。
- 创新性 ★8：游戏话题全场共鸣，趣味记忆点强。
- 老师关注点：大概率追问落地价值（"给谁用、怎么用"），需提前备好应用叙事。

## 各自优势与风险

**足球 Elo**
- 优势：全链路成本可控；有官方参照，调试与验证成本被系统性压低；Method 节有独家内容；答辩叙事完整；课程的学术模板导向与它天然合拍。
- 风险：①采集环节展示弱（唯一低分项）；②答辩抽问算法细节，全组必须吃透公式；③Kaggle 该数据集本身热门（但做"实现+验证"闭环的少，撞题实际风险低）；④主场优势结论若与文献量级差异大需能解释。

**Steam 生态**
- 优势：采集环节可拿分；答辩现场演示与话题共鸣最好；可视化素材丰富。
- 风险：①owners 精度问题贯穿始终，报告、答辩两处都要防守；②成果叙事发散，收敛成本高；③结论硬度受数据质量压制，天花板受限；④工时弹性大，容易拖。

## 综合结论

**推荐足球 Elo，倾向明确。**

理由按权重排序：
1. **误差被"标准答案"兜底**。足球项目每一步（评分曲线、预测准确率、与官方排名的对照）都有外部参照，做错了看得见、做对了拿得出证据；Steam 的核心变量自始至终是估计值，全部结论都要带星号。课程明文要求"结果可复现、不得伪造"，前者与之同构，后者要花力气自证。
2. **评分矩阵没有明显短板**。足球的最低分在采集创新（5 分），但该环节有官方数据的权威性叙事兜底，且可以用"少量手工整理对照数据"部分补位；Steam 的低分集中在执行实施与老师评价预期（6 分档），是结论层面的问题，不可通过努力消除。
3. **课程评分导向匹配**。五节学术模板（Method 要论证方法、Results 要对照基线）本质是学术规范导向的评分，足球的"协议设计 + 对照验证"正好逐条命中；Steam 的趣味优势在答辩环节才兑现，权重占比小。

**Steam 的适用条件**：若小组在以下两点上同时成立——成员普遍是游戏玩家、确有意愿在数据采集环节投入额外一周工时——Steam 仍是一个能做的项目，但需要接受结论硬度上限，并在立项时就想好 owners 问题的全部防守话术。

**执行提示（若选足球）**：把"Elo 协议设计"写成报告 Method 节的主戏；对照验证图单独占一节；答辩前全组做一次"互相抽问评分变化"的排练。K 值与进球差修正各做一组敏感性分析，把老师最容易挑的点提前变成自己的加分点。
