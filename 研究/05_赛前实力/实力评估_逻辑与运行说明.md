# 实力评估：怎样算、怎样运行、怎样使用

这套程序不是给球队贴一个永远不变的分数，而是回答：**比赛开始之前，根据已经发生的比赛，我们认为双方有多强，又有多拿不准？** 后面的年代、赛事和地域研究使用这份赛前信息，不用当场赛果反过来评价当场实力。

## 一、学习与预测按什么顺序进行

1. **先固定资料范围。** 1950年起的合资格学习比赛共38,919场。其中5,581场在1980年前帮助积累历史，8,421场是1980年后的中立场学习资料，原研究的24,917场非中立比赛仍单独保留。待定扩展没有偷偷纳入，117场人工采纳不重开。
2. **从相同起点开始积累。** 球队初始中心都是0、方差1，共享主场项初始中心0、方差0.25。它们是待学习的起点，不是“球队实际一样强”的判断。球队间相对差距比绝对数值有意义，尺度由固定的表现噪声确定；不能和FIFA/Elo积分直接换算。
3. **每天先预测，后学习。** 同一天的全部比赛只看此前完整日期的信息，先形成双方评分和胜平负概率，再共同更新当天结果。这样不会因为输入顺序，让一场下午比赛读取没有时刻信息的另一场当天赛果。
4. **主客双方都学习。** 模型用双方实力差、场地主场项和当场表现噪声解释胜平负；中立比赛场地项为0。没有单独的“客场实力参数”，不代表客队不更新。同队同日多场共享球队状态，不重复制造几份独立球队信息。
5. **区分偶然结果与持续变化。** 平常允许实力缓慢变化，也允许持续性突然位移。单次意外可能来自当场噪声；连续异常结果会累积证据，推动评分跟进变化。友谊赛通过降低信息成分比例减小学习力度。它不是“友谊赛获胜只算0.65场”，也不是额外给第二、三问的胜率乘0.65。
6. **保留拿不准的程度。** 程序保存双方方差与协方差，并保留赛前尚未发生的跳变次数混合。无比赛不直接把实力中心降下来，但长期缺少资料会增加不确定性。日末用联合高斯近似保存状态；所以这仍是经过验证的近似算法，不是精确掌握真实实力。
7. **另外修正最终预测概率。** 原评分输出之后，每年只用此前十年资料修正概率形状，再按“先预测、后更新”跟踪近期剩余偏差。这两层改善胜平负概率，不改写底层潜在实力。第三环节使用的是底层赛前实力分布，不把校正后的胜率或主场参数重新塞成解释变量。

当前底层参数为连续变化q=.03、持续跳变率.08/年、跳变尺度1.2、平局阈值.4、友谊赛信息系数.65、背景比例.05、共享场地扩散.005/年。最终预测采用共同温度/截距形状校正和.02/年动态残差。选择理由与失败过程见[第二环节验收](第二环节_验收与正式交接.md)。这些参数是有限候选中通过当前阶段要求的方案，不称为所有算法中的理论最优。

当前模型主要学习**胜、平、负**，没有用净胜球、球员或经济数据精确修正实力。原赛果口径可包含加时，点球大战不改写比赛的平局标签。

- [当前底层评分](../../data/processed/strength/jump-ratings-451ecade0bf84ee0bfb6/study_prematch_features.csv)：每场原研究比赛的双方赛前均值、方差、协方差、历史次数与信息截止。
- [最终预测与评分接口](../../data/processed/strength/strength-delivery-ca43fe498cd43ec8e21f/study_prematch_features.csv)：同24,917场，另有原始/校正后三结果概率、完整跳变分布部件及版本。
- [共同分析准备表](../../data/processed/strength/joint-preparation-6fa9d025ba40d11cd2f8/analysis_matches.csv)：连接原研究背景，保留连续实力和分布参数；第三环节直接读这张表。

这里保存的是逐场赛前记录，不能拿2024年底最终评分回填1980年的比赛。

## 三、本地怎样运行

在仓库根目录、使用本仓库虚拟环境。第一次拉取先按[快速上手](../../文档/02_环境配置/克隆仓库后的快速上手.md)配置依赖。完整历史评分需要时间，不属于每次开工必须执行的环境检查。

重新计算底层完整跳变评分：

```powershell
.\.venv\Scripts\python.exe scripts/repair_strength_jump.py --model jump_full --scope global
```

在底层已存在的前提下，重新计算最终概率和评分接口：

```powershell
.\.venv\Scripts\python.exe -m src.strength.delivery
```

严格精度对照分别在上述命令末尾加`--strict`；它用于数值核验。程序会显示实际产物目录。输入、代码或环境变化可能生成不同版本，不能把新输出路径手动改成旧版名称。当前最终概率协议默认引用已登记的底层目录；更换底层时须连配置、精度对照与采用验证一并重新绑定。

PyCharm中，第一条按“脚本路径”选`scripts/repair_strength_jump.py`、参数填`--model jump_full --scope global`；第二条按“模块名称”填`src.strength.delivery`。两条的工作目录都选仓库根目录，解释器都选自己的`.venv/Scripts/python.exe`，不要把解释器路径填进脚本参数。

## 四、第三环节怎样接着使用

第三环节不是重做评分，而是在已有逐场赛前分布上拟合共同的主胜表现模型，计算同一参考条件下的年代、赛事和地域概率差。结果模型会使用1980—2024全期标签估计系数，因此它的拟合概率不能冒称真正提前发布的比赛预测。

主入口为[analyze_strength_joint.py](../../scripts/analyze_strength_joint.py)，独立核验入口为[audit_strength_joint.py](../../scripts/audit_strength_joint.py)。正式运行情况和后续边界见阶段README及第三环节交接说明。第二环节预测验收通过，也不自动代表第三环节区间或因果解释已经通过。
