# 第一题：本地运行、验证与 A 的复现要求

更新：2026-10-23。当前支持探索性描述、标准化和点估计稳健性；区间与显著性检验未实现。输入人工核验待完成，不将程序成功理解为最终研究已完成。

## 1. 你在自己的电脑怎么跑

先打开整个仓库，工作目录必须是项目根目录，使用自己的 .venv。环境未配好先看[快速上手指南](../../文档/02_环境配置/克隆仓库后的快速上手.md)。本轮没有新增依赖，仍按 requirements.txt 配置。

在根目录的 PowerShell 依次运行：

```powershell
.\.venv\Scripts\python.exe -m src.validate --config config.json --data-version prep-3fab808178cf8ad71d88
.\.venv\Scripts\python.exe -m src.analyze_eras --prep-config config.json --analysis-config config/eras.json --stage all
.\.venv\Scripts\python.exe -m pytest -q
```

参考输出：validate 的 passed=true；分析 status=completed、inference=not_run、protocol_status=draft；基础和分类已知样本均为 26,055。测试当前参考为 48 passed，要保存自己实际的输出，不能照抄。

若只想看赛程与样本结构，改用 --stage diagnose；它不输出胜率与图。--stage describe 输出描述与标准化，all 额外运行点估计稳健性。三个阶段身份不同，不将较少产物当作丢文件。

不要将分析参数加进根 config.json；它必须与清洗时配置一致。研究范围、权重及检查在独立 config/eras.json；本次复现先保持两份配置不变。

## 2. 在 PyCharm 怎么配置

新增或复制一项 Python 运行配置，名称可填“年代分析”。

- Python 解释器：在最上方选择当前仓库自己的 .venv/Scripts/python.exe。
- 解释器选项：留空，不在这里再填一个 python.exe 路径。
- 运行方式切换为 Module name / 模块名称，填 src.analyze_eras，不直接选 src/analyze_eras.py。
- 参数填 `--prep-config config.json --analysis-config config/eras.json --stage all`。
- 工作目录：当前仓库根目录，不是 src、研究或文档目录。

应用并运行。控制台应类似“python.exe -m src.analyze_eras ...”。若启动行出现两个 python.exe 或 attempted relative import，先检查配置位置，不改相对导入来绕过问题。

## 3. 它生成什么，去哪里看

控制台显示本次 analysis_id 与 report 路径。分析身份决定表和图的位置，每次执行另生成一个运行日志目录。

```text
outputs/tables/eras/<analysis_id>/        12 张 CSV 与 data_dictionary.md
outputs/figures/eras/<analysis_id>/       3 张图，每张 PNG + SVG
outputs/logs/eras/<本次run_id>/          run_manifest、配置、检查、问题与小结
```

先读 summary.md，再看 era_summary.csv（原始计数）、reference_weights.csv（共同配方）、era_estimates.csv（调整前后）、era_contrasts.csv（年代差值）、sensitivity_results.csv（敏感性）。analysis_membership.csv 保存每条清洗记录的取舍，不要把它误认成另一份比赛主数据。

当前参考身份是 eras-7f332ed60ac443228960，参考 run 是 eras-20261023T153613611524Z-06eea9e4。你重跑后的 run_id 不同是正常的；源码、配置、数据和数值依赖版本相同时，analysis_id 应相同，已有相同表/图会复用而非覆盖。

CSV 比例是 0—1，例如 0.49 表示 49%；年代差值单位是百分点。区间和标准误为空、uncertainty_status=not_run 表示没做推断，不是标准误为零。2020—2024 只有五年。

## 4. 如何检查本次产物没有被改动

把 --verify-run 后的路径替换为控制台所示本次 report 目录下的 run_manifest.json，使用项目相对路径。下面检查仓库内参考运行：

```powershell
.\.venv\Scripts\python.exe -m src.analyze_eras --verify-run outputs/logs/eras/eras-20261023T153613611524Z-06eea9e4/run_manifest.json
```

参考应返回 passed=true、verified_outputs=24。它检查输入、输出、相关源码指纹，不重新计算。24 包含 12 CSV、字典、6 图片和 5 份运行辅助文件，不包括清单自身。

若之后改了配置或代码，旧运行验证不通过可能是正确的版本提示。先对照 code_hashes/inputs/outputs 看是哪一项变动；不要手改期望哈希消除提示。版本不同就重跑并使用新清单，旧结果保留。

同版本再运行 all 可以检查重跑一致性。报告里的 Git dirty 可能为 true，因为尚未提交；以实际源码指纹为依据，不拿旧 commit 冒充执行版本。

## 5. A 需要独立做什么

先按[原有复核清单](../../文档/05_团队协作/分工与交付/01_A_复核与改进.md)确认环境和清洗复现。然后：

1. 拉取同一版本，记录自己的系统、Python、numpy/matplotlib 版本和源码状态；不要先让 AI 改代码或参数。
2. 运行第 1 节三条命令，保存完整输出及自己的 run_manifest 路径，再对自己的清单运行 --verify-run。
3. 核对三层数量：上游 49,945=48,102+1,803+40；下游 48,102 按日期和场地变为 26,055；分类已知仍为 26,055。不能再从 26,055 扣一次 40。
4. 在 era_summary.csv 找一个年代，用 n_home_wins/n_matches 手算主胜率，确认平局在分母。
5. 在 era_tournament_summary.csv 找同年代两类赛事，用 reference_weights.csv 的 pooled_matches 配方手算调整后比例，与 era_estimates.csv 比较。优先检查 1980s 或 2020_2024；最后一组标五年。
6. 确认 eligible_venue_analysis=true 仍需 is_neutral=false；测试中包含“中立场但场地资格 true”的案例。检查点球没有改变主比分胜平负、区间确实未生成。
7. 同版本再跑一次 all，对比核心表哈希及 analysis_id。依赖或 Python 版本不同导致身份不同，先解释差异；相同环境下不能为了匹配而手改结果。数字按 CSV 的 10 位精度比较，比例和容差可用 1e-9；图像因字体/平台不同不能独自作为失败依据。
8. 打开三张图，核对样本、标签、百分比/百分点和无区间说明。自己能解释“共同配方”的意思，不仅交一句 AI 说通过。

交 `A_年代分析复现_日期.md` 到 data/external/review_submissions/A/，写本人身份、环境、实际数量、两次 run、检查结果、手算过程、问题与证据、AI 辅助范围。状态先标“已提交待复核”，组长验收后再进贡献记录。A 不独自承担尚未解决的推断理论保证。

## 6. 常见报错和后续工作

- DATASET_CONFIG_MISMATCH：根配置与清洗版本不一致。恢复对应配置或选择正确版本，不能删校验。
- INFERENCE_NOT_IMPLEMENTED：有人要求了未验收区间；本版仅支持 off/pending。
- RUN_HASH_MISMATCH：输入、源码或输出有变化，按指向文件定位，不修改清单“对齐”。
- REPRODUCIBILITY_MISMATCH：同分析身份的已有文件与本次不同，程序拒绝覆盖；交完整记录排查。
- empty_group/missing_stratum/not_estimable：相应组或检查无法估计，查看 status 与样本，不把空值填零。
- 测试临时目录权限失败：保留报错，交组长检查本机/工具沙箱；本轮正常本机测试已通过，不需要因此改研究逻辑或用管理员身份日常运行。
