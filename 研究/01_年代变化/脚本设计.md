## 实施前补充约定（2026-10-23，先于本轮代码）

本轮用户已要求开始实现，范围确定为：诊断、描述、赛事构成标准化和点估计稳健性；不实现尚未验收的区间估计。以下约定补齐原设计未明确处，后文原规划与本约定不同处以此为准，实施后另列实际结果。

- 首次配置仍标 draft，1980—2024 和五个年代作为探索性配置；两个事前指定的探索对比为 2010—2019 减 1980—1989、2020—2024 减 1980—1989。不称用户已批准确认性检验；既已事前记录，也不按结果更换对比。
- 支持 diagnose、describe、all 三阶段；all 默认运行描述、标准化与点估计敏感性。inference 仅支持 off，任何其他方法明确拒绝；不存在可由配置伪造批准后启用的统计器。模拟也未实现。
- 区间关闭时，估计表保留标准误/区间空字段及 not_run 状态，不生成 covariance.csv、cell_coefficients.csv。描述对比允许 draft，但 manifest 和报告必须标 exploratory；不作正式检验。
- 每年等权权重仅平均分析窗口内实际有已知分类比赛的年份，缺年和参考年份列表显式保存；主 pooled 权重始终只由 classified_venue 计算。标准化要求每个非零权重类别有记录，缺组为 missing_stratum。
- 为使结构诊断指标明确，组合覆盖率=实际不同无序球队对数/[G(G−1)/2]，G 是该组实际球队数；重复交手=同一无序球队对的场次；top_5_appearance_share=前五队参赛次数/全部球队参赛次数。每队主客次数之和为全体比赛数的两倍。共同球队变体为主样本各年代参赛球队集合的交集，且每场双方都属于该交集。
- 逐年剔除只报告受影响对比，保持主参考权重不变；共同球队与替代参考也沿用事前指定对比。没有合法对比或空样本仍保留状态，不强造数值。
- 敏感性网格固定 0 至 1、步长 0.01，加入主参考、替代参考及合法翻转点。翻转点是点估计的代数结果，不是推断。
- 所有正式表与图先在内存完成并自动核对，然后按既定 outputs/tables|figures|logs/eras 布局发布，以 success manifest 最后写入为完成标志；失败不覆盖旧内容。analysis_id 纳入请求阶段、分析源代码/契约哈希与数值依赖版本；运行时间只进入 run_id。新增独立 --verify-run 用于检查现有运行记录的输入与输出哈希，不重做分析。
- 上游排除分布只使用 manifest 绑定 lineage；遇窗口外记录用原始行号关联已登记 raw/results.csv 的日期，不用 match_id 候选关系猜日期。不存在可绑定问题明细时不自行寻找最新报告。先保留清洗与分析两个层次的数量，明确日期筛选在样本里再次执行的含义。
- 原计划完整参数模型和推断验收接口暂不写空实现；inference.py 只负责明确的关闭/拒绝边界。字典逐列列类型、单位、缺失与主键；未实施的文件清楚注明，不以空输出冒充。

## 先读结论

建议采用 **一个运行入口、六个内部模块**。使用者只运行一次，内部按读取取样、统计、标准化、推断、检查、报告分工。不是六个必须手动依次运行的文件，也不把所有内容塞进一个大脚本。

描述统计、固定权重合成与多数稳健性检查可以先实施。区间模块默认关闭，完成方法验收后再启用；不会阻止已有描述结果生成，也不会悄悄改用普通独立样本区间。现有 clean.py 和清洗后的 CSV 不改写。

## 1. 文件怎么拆，为什么

以下文件均已实现；inference.py 仅提供明确的关闭/拒绝边界，不包含未验收估计器：

```text
src/
├── analyze_eras.py        原基线运行入口；当前会员接入由scripts外层控制
└── eras/
    ├── __init__.py        包标识，不放业务逻辑
    ├── data.py            输入验证、配置、类型转换与取样追踪
    ├── statistics.py      原始统计、分层计数与赛程结构诊断
    ├── standardize.py     固定参考权重、统一构成与年代对比
    ├── inference.py       待验收的方法、联合协方差及验证模拟
    ├── checks.py          统计对账、稳健性检查与问题记录
    └── reporting.py       按固定规范写表、画图、保存清单
```

一个大文件开始较快，但方法变化时容易同时改动筛选、统计与图表，难以判断差异来源。全部做成独立命令又会迫使组员手工传文件，容易混用版本。这里保留单一入口，内部函数按目的拆开，A 可以单独核对统计与权重，后续替换推断方法也不影响前面的计数。

不再为每张图、每种检查创建一个脚本；先维持这六个模块，确有独立复杂度后再拆。五步研究规划不要求机械对应五个 Python 文件。

## 2. 与已有数据的接口：本轮已核查的事实

### 2.1 读什么文件

事实主输入是 `data/processed/<data_version>/matches_clean.csv`，同时读取同目录 `dataset_manifest.json`；当前还须读取已校验的identity_manifest及match_identity.csv，不能只使用事实表取样；当前参考版本为 prep-3fab808178cf8ad71d88。

本轮实读确认 CSV 为 **36 列**，清洗文件 SHA-256 为 `69ba00073970fe011a62f5871c08ace6285d7fe75d5a0d79afdac0ef972de9dc`，与 manifest 一致。运行现有 `src.validate` 返回 passed=true：主键唯一、逐行去向、计数、字段值、资格与排序检查通过。该结果只验证清洗契约，不等于完成事实核验或本题统计。

验证清单仍为 human_review_pending=true、frozen=false。默认允许生成注明“初步”的描述结果；不能只因程序验证通过而标成最终冻结数据。

### 2.2 必须使用的字段及含义

- 身份与追踪：match_id、source_record_id、source_file、source_sha256、source_record_no。match_id 作为分析主键保留，不重新按日期双方造 ID。
- 日期：date、year、decade_start。用完整 date 筛选并检查派生年一致；重新生成 analysis_era_id 和起止日期，避免将 2020—2024 标为完整十年。
- 球队：home_team_id、away_team_id；显示可用 home_team、away_team。检查身份非空且双方不同，主客交换仍使用相同球队 ID。
- 赛果：home_score、away_score、outcome、goal_difference、result_basis。outcome 仅 home/draw/away，派生 home_win=1 当且仅当 outcome=home；核对比分一致。
- 场地：is_neutral、eligible_venue_analysis。**场地资格为 true 只表示中立标记可判断，并不表示非中立。** 必须同时要求 is_neutral=false。
- 赛事：tournament、tournament_group、eligible_tournament_analysis。已知分类样本须在基础样本上再要求赛事资格 true、分类为 friendly 或 non_friendly；unknown 另外计数，不能静默丢弃。
- 状态：review_status、time_split。review_status 是既有审查状态，不将未知字符串擅自解释为批准；time_split 为 warmup/train/valid/test，第一题按明确日期取样，不只取 train，也不将现有验证/测试分界当年代标签。

CSV 的 true/false 是小写文本，读取后显式解析，不能 bool("false")。is_neutral 空值按未知处理；资格字段非法值属于输入错误，不填 false 掩盖。比分与计数解析为整数，日期解析为 ISO 日期；不依赖表格软件的日期转换。CSV 用 utf-8-sig 读取。

主比分口径须为 after_extra_time_excluding_shootout。shootout_status、shootout_winner_id 不用于改写主胜；辅助点球 unresolved 不自动排除一个本来合格的比分记录。第一题不要求 Elo、阵容、地区等不存在的字段，也不因为资料未到齐创造空占位列。

### 2.3 正确复用现有验证，不破坏清洗版本

现有接口是 `src.validate.validate_dataset(root, config, data_version)`。它不仅检查主表，还要求 config 与 manifest 内清洗配置完全一致，并校验原始快照、输出哈希和 manifest 指定的逐行去向文件。分析入口应先调用它，保存本次返回报告；失败则停止，不降低检查标准。

因此，**分析参数另放 `config/eras.json`，不加进现有根目录 config.json。** 命令分别接收清洗配置和分析配置；改变根配置后再拿旧版本运行，会触发已有 DATASET_CONFIG_MISMATCH，这是合理保护。

来源追踪优先读取数据 manifest 中的 lineage_path 及 lineage_sha256。当前指向 clean-20261021T143700805474Z-127f4584，而不是用户最新重跑目录；不能见到较新的目录便自行换来源。若额外引用某个清洗 run 的问题/隔离表，显式指定并核对其 data_version 和输入身份，不全盘搜索“最新”。基础样本可只用主表，未经绑定的辅助报告不得用于排除统计。

### 2.4 配置应包含什么

分析配置采用 eras-config-v1，字段包含：data_version、analysis_start、analysis_end、eras（id/start/end/label）、primary_contrasts（id/earlier/later）、reference_scheme、alternative_reference_schemes、inference、sensitivity、random_seed、protocol_status。

- 主参考建议 pooled_matches，补充 equal_years；不是 Elo 的 K/H/G 参数。
- inference 默认 mode=off、validation_status=pending；启用时必须指定 method_id、method_version、验收证据路径及其哈希、临界值规则。
- sensitivity 明确逐年剔除、共同球队等检查的范围；不默认逐队重算全部复杂推断。
- protocol_status=draft 时只允许结构诊断及明确标注探索的描述；不能输出正式确认性对比。窗口、分组和主要对比确定后保存 confirmed 及真实决定引用，不能由程序自动“批准”。
- 时间组不得交叠；覆盖分析窗口内的日期，最后组真实截止到 2024-12-31；结束日不得晚于当前数据 cutoff。
- primary_contrasts 未填写时可统计各组，但不自动生成全部十组正式检验或替用户挑“最大变化”。

本版 config/eras.json 已可运行，另有 protocol_decision 字段保存决定引用。配置字段严格校验；inference 仅接受 off/pending，上述方法批准与模拟配置属于后续设计，不接受伪造批准后直接启用。

## 3. 一个入口如何完成五步

以下调用已实现并验证（推断仍关闭）：

```text
python -m src.analyze_eras --prep-config config.json --analysis-config config/eras.json --stage describe
python -m src.analyze_eras --prep-config config.json --analysis-config config/eras.json --stage all
```

入口只接收参数、检查阶段依赖、分配 analysis_id/run_id、调用模块、收集检查、控制发布，不直接写统计公式。

describe 完成已批准范围内的取样、描述、构成与标准化；diagnose 可只输出不使用赛果的结构诊断；all 加入已配置的稳健性检查及通过验收的推断。inference=off 时 all 的推断阶段明确记 not_run，不产出看似已完成的空白“显著性结果”。若用户显式请求推断但协议未通过，报错，不静默退回描述并返回成功。

内部数据流为：验证与协议 → 固定样本及追踪 → 年代/赛事单元统计 → 固定权重与线性对比 → 已验收推断（可关闭）→ 稳健性检查 → 全部对账 → 正式保存。

## 4. 六个模块分别做什么

### 4.1 data.py：只在一个地方定义取样

本版函数：load_analysis_config、load_validated_dataset、boolean、select_samples、sample_id、upstream_flow。解析在读取函数内完成，取样函数同时返回逐行成员表。

生成两份明确命名的只读逻辑样本：base_venue（全部合格非中立场）、classified_venue（在前者中赛事已知且资格成立）。所有模块接收同一批已解析记录与上下文，不各自重新读取、重新筛选。内部采用有字段约束的记录或 DataFrame，模块对数据不原地修改。

analysis_membership 为每条清洗记录保存是否进入两个样本、年代、日期和原因。多重原因保留列表，再按固定优先级提供一个 primary_exclusion_reason，用于互斥计数；不能把多原因相加当成排除总数。基础样本与赛事已知样本分别有 sample_id，由输入身份、筛选规则与纳入 match_id 集合确定。

清洗前的 49,945→48,102/1,803/40 是上游清洗流程；本题从清洗记录再取样是下游流程，分别报告，不将隔离 40 再从已清洗表减一次。没有可靠日期的历史问题只进 undated 汇总，不能造日期硬塞年代。

### 4.2 statistics.py：计算事实与结构，不计算区间

本版函数：summarize、schedule_rows、build_statistics、team_set。一个聚合函数按表名生成年代、逐年、赛事单元和赛程表；上游排除分布由 data.upstream_flow 提供。

基础统计始终保留全样本版；调整前后比较另用 classified_venue 的统计，不混淆分母。按年代、年份、年代×赛事计算胜平负和净胜球；另生成逐队主客次数、不同对手数、组合覆盖和重复交手、头部集中等诊断。非共享球队的共同时间环境诊断保留日期和赛事信息。

日期组即使无比赛，也保留 n=0、比例缺失和 empty_group 状态，而不是胜率零。分层计数输出 n_home_wins、n_draws、n_away_wins、n_matches，不仅保存浮点比例，便于 A 独立复算。

### 4.3 standardize.py：计算参考配方与对比系数

本版函数：build_reference、era_rates、contrasts_for、build_standardization。权重敏感性由 build_standardization 统一生成。

从固定 classified_venue 计算主参考和补充参考；权重只用场次数，不看赛果。保存 reference_id、参考样本 sample_id、方案、两类占比、所用年份与配置哈希。权重和应为 1，各年代引用同一 reference_id。

合成 s_t=w p_tF+(1-w)p_tN，原始同样本比例按实际计数计算并独立核对。将年代差值及 C=Δr−Δs 保存为明确方向的描述性结果；后续推断时再构造统一向量 c，不能由两个模块各写一套差值公式。

如果某年代缺某个参考权重非零的赛事组，该参考结果为不可估计，写 missing_stratum 与缺失值；不填零、插值或自动合并年代。w 为零的组可以按精确定义不贡献，但主要方案仍报告覆盖状况。两个组必须以统一顺序 friendly、non_friendly 对齐。

### 4.4 inference.py：负责推断及方法验收，不改变统计目标

本版只有 require_off、without_uncertainty：明确拒绝未实现的方法，统一生成 not_run/空区间字段。下文是后续推断与模拟的设计要求，尚未实现，不能调用配置绕过。

启用前核对方法版本、验收文件与输入适用范围；不同研究数据或协议变化时不能无条件沿用旧批准。饱和单元模型系数须复现分层主胜率。共享球队方法使用双方同一 ID，允许跨角色和跨年代关联；时间共同冲击方案未定，不在设计里偷偷实现一个未经核查的替代器。

保存单元系数、带参数索引的完整联合协方差，以及每项估计的标准误/区间/临界值规则。标准化与原始结果来自同批比赛，直接用 c'Vc 计算差异，不当成独立样本。不启用时，描述估计行的 uncertainty_status=not_run，方法和区间为空，而不是把标准误填零。

模拟验收是独立运行任务，有自己的 simulation_run_id、种子、机制、次数、覆盖率、蒙特卡洛误差和证据哈希；all 不在每次画图时重新运行大量模拟。包含共享球队、异号角色、集中赛程及共同时间冲击。验证结论未通过时，拒绝正式推断；不能按实际 p 值选择估计器。

### 4.5 checks.py：一部分验证正确性，一部分检查稳健性

本版函数：validate_tables、run_sensitivity、collect_issues。检查不通过抛出带代码的错误，变体及问题单独生成记录。

正确性检查包括：样本嵌套、主键唯一、胜平负计数和、比例和、分层与总数对账、同样本原始比例一致、权重和、线性对比一致、单位一致、无非有限数及协方差异常。严重错误阻止发布，不能图已画出来就认为成功。

稳健性检查包括固定主权重逐年剔除、共同球队、每年等权参考、整个 [0,1] 权重范围的差异函数和翻转点；每个变体有 variant_id、parent_sample_id、实际 sample_id、reference_id。主检查保持原参考权重固定；重算权重另命名，不掩盖目标改变。

变体出现空组就标 not_estimable，继续报告其他变体，不制造零差异。初版以点估计稳健性为主，不要求每个变体都运行区间；若需要推断，必须带对应配置与新协方差。稳健性检查不代替相关性处理。

### 4.6 reporting.py：只负责可靠保存与展示

本版函数：table_artifacts、dictionary、figure_artifacts、publish_outputs、verify_run；运行小结和清单由入口统一保存。图表在内存生成后发布，绘图函数只消费已计算表。

统计先生成结构化结果，图只读取结果；不在画图函数里重新筛样或计算权重。图注明确全样本/同样本、年代范围、样本量、参考方案、初步状态及区间方法；2020—2024 标为五年。区间未做就不画误差线，不把描述波动冒充置信区间。

README 的研究结论由实际结果与复核更新，程序只生成待审阅小结和文件链接，不自动改写研究历史、宣布人工复核或发布 GitHub。

### 5.1 每张核心表的最小字段

以下为 schema eras-tables-v1；实现时固定字段顺序、主键及字典，不随 pandas 索引输出新增匿名列。

- **analysis_membership.csv**：data_version、match_id、source_record_id、date、analysis_era_id、in_base_venue、in_classified_venue、primary_exclusion_reason、exclusion_reasons。唯一键 match_id；每条清洗记录一行，不包含上游已经隔离的记录。
- **sample_flow.csv**：flow_id、stage、parent_stage、reason、n_records、basis、status。basis 标明 upstream_raw 或 processed_matches；互斥排除可相加，多原因问题列表不可当流程计数。
- **era_summary.csv / year_summary.csv**：sample_id、sample_name、period_id、start_date、end_date、n_years、n_matches、n_home_wins、n_draws、n_away_wins、home_win_rate、draw_rate、away_win_rate、mean_goal_difference、status。唯一键 sample_name+period_id；两个逻辑样本可能恰好包含相同比赛，sample_id 可以相同，故以 sample_name 区分视图。
- **era_tournament_summary.csv**：sample_id、analysis_era_id、tournament_group、n_matches、n_home_wins、n_draws、n_away_wins、home_win_rate、draw_rate、away_win_rate、mean_goal_difference、status。两类顺序固定，空组显式表示。
- **team_schedule.csv**：sample_id、analysis_era_id、tournament_group、team_id、n_home、n_away、n_matches、n_distinct_opponents。n_matches=n_home+n_away；全队参赛次数之和为两倍比赛数。
- **schedule_diagnostics.csv**：sample_id、analysis_era_id、tournament_group、metric、value、unit、status；保存集中度、覆盖和最大重复等指标，定义写进字典。
- **reference_weights.csv**：reference_id、reference_sample_id、scheme、tournament_group、weight、reference_start、reference_end、n_reference_matches、n_reference_years、status。唯一键 reference_id+tournament_group；明确 equal_years 参考年份。
- **era_estimates.csv**：estimate_id、sample_id、analysis_era_id、estimand、reference_id、estimate、unit、standard_error、ci_lower、ci_upper、confidence_level、method_id、method_version、uncertainty_status、status。estimand=observed_rate 或 standardized_rate，unit=probability。
- **era_contrasts.csv**：contrast_id、sample_id、earlier_era、later_era、estimand、reference_id、estimate、unit、standard_error、ci_lower、ci_upper、confidence_level、method_id、method_version、uncertainty_status、status。方向固定“后期减早期”，unit=percentage_points；命名 observed_difference、standardized_difference、composition_adjustment_difference。
- **weight_sensitivity.csv**：contrast_id、sample_id、weight_friendly、difference_pp、flip_weight、status。预设固定网格包含 0、1，额外纳入主权重与合法翻转点；非存在的翻转点留空并说明平行/恒零/区间外。
- **sensitivity_results.csv**：variant_id、check_type、parent_sample_id、sample_id、reference_id、contrast_id、n_matches、estimate_pp、baseline_estimate_pp、change_from_baseline_pp、status、reason。样本减少不等于一定可估计。
- **cell_coefficients.csv / covariance.csv**：系数有 parameter_id、年代/类别与 estimate；协方差采用 row_parameter_id、col_parameter_id、covariance 的长表，完整参数顺序另存 manifest，不假定 Excel 行号就是参数身份。

所有表均由 analysis_id 所在目录和 run manifest 绑定；不必每行重复长哈希，但每个 sample_id/reference_id/estimate_id 都能定位来源。data_dictionary.md 说明字段、类型、枚举、单位、主键、缺失含义及排序。

### 5.2 数字、文本和缺失值规范

- CSV 使用 utf-8-sig、LF 行尾，逗号分隔，必要字段按标准 CSV 引号转义；字段顺序固定，不输出 DataFrame 索引。
- 日期 YYYY-MM-DD；计数十进制整数；布尔值小写 true/false；浮点固定 10 位小数，与现有 src.data_contract.csv_bytes 规则衔接。按已声明主键稳定排序，比较使用内存原值，写出前才格式化。
- 比例与标准误保存在 0—1 概率单位；年代差值、相应标准误和区间统一乘 100，以百分点保存。字段或 unit 明确单位，不能标准误未换单位而差值已换。
- 缺失值为 CSV 空字段、JSON null，配 status/reason；不输出 NaN/Infinity 或用 0 代缺失。空组率为缺失；未运行区间为空且 uncertainty_status=not_run。
- 比例点估计必须在 [0,1]；若某个已选近似区间超出范围，不静默裁切，应标记并按方法协议处理。区间参数与界限都记单位，不把初步区间藏在图的显示范围外。
- JSON UTF-8、LF，键顺序稳定，禁止非有限数。时间戳采用 UTC ISO 8601，版本与身份使用字符串。CSV 的行 ID 等字段在 Excel 中按文本查看，程序不因软件显示变形修改原始值。
- PNG 建议 300 dpi，配 SVG；统一字体与图例，中文字体缺失明确告警。数字表是验收依据；图片受字体/绘图库影响，不要求不同机器图像字节必然一致。

### 5.3 身份、可复现与失败处理

analysis_id 由输入数据/manifest 哈希、已绑定辅助证据哈希、分析配置、所请求阶段、模块源码与规则版本、影响数值的依赖版本共同生成；不包括本次时钟。不同阶段不会因配置相同而错误复用不完整产物。reference_id、sample_id 各有确定性身份。run_id 包含 UTC 时间及唯一后缀，同一分析可对应多次运行。

run_manifest 至少保存上述身份、真实 git commit 和 dirty 状态、相关源码哈希、Python/依赖版本、配置与输入路径/哈希、样本计数、权重与方法身份、协议状态、各阶段执行状态、输出路径/哈希、检查结果、限制与复核状态。未提交改动保存实际源码哈希，不拿旧 commit 当作执行代码。没有人工验收时 review_status=pending。

同样输入和环境重跑，核心 CSV 期望哈希一致；依赖版本或数值计算平台不同，不承诺浮点二进制相同，应记录环境并按指定容差核查。固定求和/排序次序、随机种子与模拟次数；种子相同不等于任意库版本都相同。

本版先在内存生成表与图并对账，检查所有目标文件是否冲突，再逐个原子写入；多个输出目录以最后的成功 manifest 作为完成标志。已有 analysis_id 内容相同则复用并新记 run；不同则报 REPRODUCIBILITY_MISMATCH，不覆盖旧成果。中断可能留下没有成功清单的部分文件，不能将其当正式结果；错误记录留在失败 run 的 manifest。

## 6. 报错和验收

issues.csv 字段固定为 issue_id、run_id、stage、severity、code、sample_id、match_id、field、message、action、status；没有对应比赛时 match_id 为空。不将整行个人信息、绝对用户路径或敏感信息写入公共报告。

输入版本不存在、哈希不符、缺列、布尔解析失败、主键重复、比分/赛果矛盾、分组交叠、上游配置不匹配：error，停止。空组和变体不可估计：review，保留缺失与原因。人工核验未完成：warning，允许明确标注的初步描述，不能宣告最终冻结。显式要求推断但协议未验收：error；默认 off 则 not_run，不是假报错。

建议退出码：0=所请求阶段完成且自动检查通过，可有已披露限制；1=输入/计算/发布失败；2=请求的协议或方法尚未获准执行。0 不代表事实核验完成或研究结论成立，与现有审计返回码分别解释。

实现后的必要验证包括：

1. false 不被当 true，场地资格 true 的中立场仍排除；日期边界、比分和点球口径正确。
2. 全样本与分类已知样本明确分开，数量和主键可对账；历史上游隔离不重复减。
3. 五步规划的假设例子复现 58%/57% 未调整、55%/60% 标准化，且交换年代方向只反转差值。
4. 权重统一、缺组不填零、比例与百分点单位正确、同样本直接与分层原始比例一致。
5. 固定权重的逐年剔除与重算权重变体不混淆；空组/零分母按规范报出。
6. 仅在实施推断时，核对共享球队枚举、联合 c'Vc、角色异号与共同冲击模拟、非有限/负方差处理。
7. 固定输入重跑核心表一致，失败不覆盖旧版；图区间状态与机器表一致。

本版已实现描述与点估计部分。全仓库 48 项测试通过，含 14 项新增年代分析测试；推断枚举、协方差和覆盖率模拟尚未实现，不能称第 6 项推断验收已通过。

## 7. 建议的实施顺序

先实现入口、data、statistics 和最小 reporting，得到可复核的样本及结构诊断；再实现 standardize 与正确性检查，最后加入点估计稳健性。根据诊断完成统计方法审查后，实施 inference 与相应验收，不让方法尚未确定阻塞所有描述工作。
